## 备份与编码安全规则（主人 2026-08-10 确立，长期生效）
> 背景教训：2026-08-09 曾因 GBK 混编 + UTF-8 第三字节损坏，导致《对话知识点记录.md》2000+ 处乱码、误删换行；E 盘备份仓库也保存过损坏版本。以下规则防止再次发生。

### 编码标准
- **所有学习 md 文件统一 UTF-8 无 BOM 编码**
- **禁止**用记事本/编辑器"另存为 ANSI / GBK / UTF-8 (带 BOM)"覆盖保存
- **禁止**把含 `�`(U+FFFD) / `锟斤拷` / `烫烫烫` 的乱码文本复制粘贴进 md 文件
- 若文件乱码（UTF-8 解码失败 / 含 U+FFFD）→ **视为损坏，禁止直接备份或推送损坏文件**

### 纯文字标准（主人 2026-09-19 确立，长期生效）
> 背景教训：2026-08-07 一次 GBK 保存中 emoji 无对应编码、被写成 `?`，本领域相关 md 约 234 处 emoji 永久丢失（不可逆）；编码校验只查 U+FFFD，而 `?` 是合法 ASCII，完全检测不到。

- **所有学习 md 一律禁用 emoji**，状态一律用纯文字：`待开始` / `进行中` / `已完成` / `未完成` / `已复习` / `需再复习` / `红标`
- **强调用纯文字方括号标记**：`【重点】` `【注意】` `【补充】` `【工具】` `【引用】` `【深入解析】` `【对照】` `【思考】`
- **AGENTS.md 规则文件例外**：规则文件为说明用途可含 emoji 示例，不受本条限制
- **校验补充**：学习 md 不应出现 `? ` / `?? ` 形式的状态标记，发现即为 emoji 丢失或 GBK 残留，须先修复再备份

### 损坏处理流程（如再遇乱码）
1. 先把损坏稿复制存档到 `C:\Users\Administrator\AppData\Local\Temp\opencode\`（勿删）
2. 回退 git 干净版（`git log` 找最近无损坏提交）或对 GBK 文件做 GBK→UTF-8 转码

### 编码校验命令（PowerShell，项目根目录执行，$f 换成文件名）
```powershell
$f = "对话知识点记录.md"; $b = [System.IO.File]::ReadAllBytes("$f")
try { $t = [System.Text.UTF8Encoding]::new($false, $true).GetString($b) }
catch { throw "不是合法 UTF-8，禁止备份！" }
if ($t.Contains([char]0xFFFD) -or $t.Contains("锟斤拷")) { throw "含乱码，禁止备份！" }
else { Write-Host "UTF-8 OK: $f ($($b.Length)B)" }
```
